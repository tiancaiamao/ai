# Reclaim Code Entropy（ai 仓库专用）

代码熵 = 没有当前承重理由的维护面：多余的表示、状态、API、分支、配置项、测试，产品必须持续维持其一致性。

**核心规则：扫描器只产生候选；只有消费方、所有权、历史、验证四类证据能证明删除。** 宁可少删几个证明过的，不要列一堆猜的。找到没有可安全删除的东西也是合法结果。

## 模式

- **audit**（"查一下"、"找找"、"review"）：只读，产出按 confidence / risk / 净维护面减少排序的候选列表。不改任何文件。
- **apply**（"删掉"、"清理"、"化简"）：实施用户要求的、证据最充分的删除，并完整验证。
- 删除**可达的用户能力、公开协议字段、持久化格式、兼容路径**属于产品决策：先向用户摆出可见的取舍，除非用户已经明确拍板。

## 保护性约束（默认有意设计，不提删）

没有用户明确推翻，以下不作为"低价值清理"候选：

- **`pkg/protocol` 的 ACP 协议结构体**——对外契约，复用共享协议结构体是 AGENTS.md 硬约束
- **`pkg/session` 的 JSONL 持久化格式**——AGENTS.md 要求兼容
- **`docs/adr/`**——不可变。它是本技能的"决策记录"来源：判定 supersession 时以 ADR 为准
- **middlewares hook**——可能由 `agent.yaml` 配置驱动，删前必须查配置消费方
- **trace event**（`pkg/traceevent`）——Perfetto 外部工具消费，不能靠仓库内 grep 判断无消费
- **信任边界上的验证**：auth、权限、数据丢失防护、资源静默（quiescence）清理，一律不动

## 动态可达性清单（grep 会漏的地方，每个候选必须显式查过）

- tools 在 `pkg/app/rpc_setup.go` 注册，`agent.yaml` 可按名过滤
- skills 按字符串/目录名加载（`~/.ai/skills/` + `.agents/skills/`）
- 配置项可能由环境变量注入，不只是 config.json
- `ai serve` / `ai acp` / CLI 子命令是独立入口点，消费方不在主循环里
- 事件名、wire 字符串、run/session 元数据键：按字符串全仓搜，不按符号搜

## 候选证据链（每个候选必须走完）

1. 全仓搜：符号名、文件路径、配置键、事件/wire 字符串、字符串形式的调用
2. 分类每个命中：production（运行时源码、shipped 配置、真实入口）/ non-production（测试、文档、快照）/ ambiguous（fixture、反射式注册、外部消费）——ambiguous 必须人工判定后再分类
3. 读 ADR 和 CHANGELOG：这个面当初解决什么问题？问题还在吗？新证据是否压过当初的理由？
4. 说清删掉放弃什么能力/行为，哪怕答案是"无可观察损失"
5. 估算**净减少**：删掉的代码 + 仅为它存在的测试 + 文档 + 配置 + 概念，减去替换胶水与迁移成本
6. 命名"最小决定性检查"：如果这次化简错了，哪个检查会失败

**降级或放弃候选**（任一成立）：存在真实生产/外部消费方；无法排除动态可达或兼容义务；现行 ADR/决策记录支撑且新证据压不过；改动只是把复杂度搬走而没有收缩合同；候选太小、不确定或超出请求范围。

候选证据记录格式：

```text
[confidence / risk] 候选
evidence: 生产消费方；动态/公开/兼容性检查结论；当初的设计理由
cut: 精确删除的代码、制品、依赖、概念
tradeoff: 损失的可观察能力或行为
verify: 最小决定性检查；净减少估算
```

## 实施（apply 模式）

1. **feature branch + PR，永不 commit main**（仓库硬约束）
2. 一次一个所有权边界；修熵的源头，不逐个打补丁
3. 端到端删合同：声明、实现、分支、只为被删行为存在的测试、导出、配置、文档、快照。保留幸存合同自身的测试——测试是证据，不是不可触碰的规格，也不为了行数随便删
4. 镜像状态收敛到承重表示上，不要用"同步包装器"替代两个事实
5. 优先：删除 > 标准库 > 已装依赖。新依赖只有在其删掉的实现和测试负担大于胶水与供应链成本时才引入
6. 无兼容义务就不留 shim；有兼容义务就显式迁移，不静默删

## 验证

每批非平凡改动后：

```bash
make fmt              # 必须过
go build ./...
go test ./pkg/<改动包>/...   # 先窄后宽
make test
git diff --check
```

再全仓搜一遍被删的符号、字符串、路径和过期文档。验证失败时判定：候选其实是承重的 / 实施不完整 / 基线本来就是红的——只回滚当前批次或补证据，不削弱有意义的检查来强行通过。

## 报告

- **audit**：按 confidence / risk / 净减少排序；高价值但证据不足且缺失证据可操作的候选单独列出
- **apply**：删了什么合同/重复事实、可度量的文件与行数、用户可见或兼容性变化、完整验证命令及结果、有意保留的高价值候选及原因
